# 棋眼 · Go Lens

Android 离线围棋屏幕助手。读取用户授权共享的屏幕，识别标准木色棋盘上的黑白棋子，以 KataGo 提供下一步建议。棋局分析不联网，图像只保存在运行时内存，不自动落子；仅主动点「检查更新」时访问 GitHub 公开发布接口。

## 使用

1. 安装 APK，设置当前轮到黑/白、贴目与分析时长。「快速」使用 b10 模型，「均衡/深入」使用更强但更慢的 b15 模型。屏幕模式自动识别 9、13、19 路；棋盘大小设置用于离线试棋及手动校准备用。
2. 点「开始屏幕辅助」，按系统提示授予悬浮窗权限；返回再次开始，并亲自授权共享整个屏幕。
3. 打开腾讯围棋的完整棋盘，等待自动定位和校准，正常使用不需要点选棋盘角。把悬浮窗拖到棋盘外，避免遮挡。
4. 棋盘移动后会重新定位。如果主题无法自动识别，可用「手动校准」备用：依次点左上角、右下角交叉点，检查彩点重合后确认。
5. 每次棋盘变化，等待两帧稳定后自动分析。**直接在棋盘交叉点画圈**：绿色 1 为首选，橙色 2/3 为备选。圈允许手指点击穿透，可直接在棋盘落子。屏幕常驻约 36dp 的半透明可拖动按钮；展开面板宽约 200dp、半透明，8 秒后自动收起，点标题也可立即收起；棋盘变化时提前收起，避免盖住落子确认区。
6. 标准腾讯围棋竖屏界面会结合左右棋子标识与高亮计时框确认黑白轮次，避开未确认的预落子；只在左侧玩家自己的回合标点，对手回合撤下建议。普通棋盘则依据棋谱跟踪。有人停一手时手动点「停一手」。无法判断轮次时可点「轮到黑/白」切换。
7. 点「暂停」暂停分析；点「关闭」或系统共享通知「停止」，结束屏幕读取与引擎进程。
8. 主界面点「检查更新 · GitHub」，应用只在此时查询公开发布的版本信息。如果有新版，可点「下载并安装」；棋眼在应用内下载 APK 并显示进度，完成后打开 Android 安装界面。首次可能需要允许棋眼安装此来源的应用，系统安装确认仍由你操作。检查失败时可打开发布页手动下载；无需 GitHub 登录。

## 第一版边界

- Android 10+、ARM64；主要针对竖屏标准木色棋盘。非标准棋子、特效、落子动画或坐标偏移可能需要重新校准。屏幕旋转/尺寸变化后需重新启动共享。
- 一次截图无法可靠推断当前轮次或此前劫争历史。应从开局开始观察；自动定位到相同局面时保留历史，手动校准或切换轮次会重置历史。已有历史内保留提子、停一手和重复局面信息。
- 自动识别到与当前预设轮次相反的新棋子时，尝试修正开局轮次或补记一次可能遗漏的停一手。漏看多手但黑白交替明确时，可重建当前局面继续分析；短间隔提子有保守的接续检查。标准腾讯界面会识别亮起的计时框和绿色确认按钮，等待落子真正完成，并在稳定后重新同步。重建时历史会重置；复杂提子、悔棋等无法可靠恢复的情况会撤下建议并要求确认。建议先在练习/复盘或允许辅助的场景中验证。
- 使用 KataGo 1.15.3 的 Eigen CPU 后端。快速档使用 2020 年 b10c128，均衡和深入档使用 2020 年 b15c192；它们在官方同一训练系列的评级高于旧版 b6c96，但不是最新的大型网络，也不保证胜局。分析档位限制搜索时间，首次载入模型及识别另需时间。
- 「棋盘图」是识别结果的缩略棋盘，不在腾讯围棋原界面自动点击或摆棋。
- 直接画圈使用透明悬浮窗。Android 12+ 对这种窗口的触摸穿透设有透明度限制；目前以 0.6 窗口透明度通过常规手势，具体机型仍需实测。
- 没有自动开启悬浮窗或屏幕共享权限，用户可随时撤销。应用仅为主动检查、下载更新申请网络和安装来源权限；截图、棋谱和模型分析不上传。下载使用应用专属目录，无需共享存储权限；应用不申请麦克风、相机、通讯录或无障碍权限。

## 构建

Java 17+；Gradle 8.14.3 / AGP 8.13.2；Android SDK 36。

原生引擎采用 NDK 28.2.13676358、CMake 3.22.1。运行 `build-native.ps1` 前设置 `ANDROID_SDK_ROOT` 或 `ANDROID_HOME` 指向已安装的 Android SDK。C++ 静态运行库、ARM64、16KB ELF 对齐；KataGo 可执行文件通过 `jniLibs/arm64-v8a/libkatago.so` 安装在应用原生库目录并由应用启动。

```powershell
.\build-native.ps1
gradle :app:assembleDebug :app:assembleDebugAndroidTest :app:lintDebug
```

`local.properties` 写入 SDK 路径。本机调试包用于侧载验证；不包含发布商店的签名材料。

## 验证

电脑端 20 项测试包含提子、非法落子、劫争、停一手、漏记停一手后的恢复、连续落子与短间隔提子接续、坐标转换，9/13/19 路合成截图识别、遮挡拒绝、棋盘标点不误识别、自动定位、棋盘移动、密集棋子定位、腾讯计时框和确认按钮检测，以及更新版本比较与可信 APK 链接筛选。

2026-09-22，自动校准改动前的版本通过真机 4 项测试，包含真实 KataGo 连续分析两步：19 路开局、32 次搜索预算，启动后首次 774 毫秒，第二次 179 毫秒。这是引擎调用耗时，不含屏幕识别时间，也不是所有局面的速度保证。

2026-09-23，用腾讯围棋实机画面验证：约 36dp 半透明按钮、棋盘标点正常；0.7.0 在中途局面识别黑棋轮次并恢复棋盘标点。0.7.2 加入左右棋子标识识别，在玩家执白的实机画面中显示“白棋建议 Q4”，绿色首选圈与 Q4 交叉点重合，展开面板约 8 秒后自动收起。0.8.0 增加只在玩家回合显示建议、棋盘变化时提前收起面板；已在白棋回合看到标点，对手回合行为与复杂提子、悔棋仍需更长时间验证。

0.8.1 修复亮木色棋盘上白棋被漏识别的问题。原阈值要求白棋亮度高于棋盘背景 22，实机截图中的白棋仅高约 21，导致建议圈落在已有白棋上；现在结合低饱和度与亮度差识别，并增加亮棋盘渐变白棋回归测试。此修复通过本机测试，更多腾讯棋盘主题仍需实战检验。

0.8.2 修复腾讯围棋最后一手三角标记使整颗棋子漏识别的问题，改用抗局部异常像素的判定。每帧还会独立抽样棋盘所有空点，以及建议点；若发现疑似漏认棋子，会暂停建议并重新定位，最后绘制时也会跳过疑似已占用点。增加亮棋盘白棋、黑棋、三角标记及空点回归测试。

0.8.3 在用户提供的密集 13 路终局截图上发现旧自动定位会失败，放宽可见网格峰值要求，加入匿名合成棋盘回归测试。模型升级为快速 b10、均衡/深入 b15，并使用按模型命名的本地缓存，升级后不会误用旧 b6 文件。在 vivo V2302A 上，13 路空棋盘、64 次搜索预算：b10 首次约 1.9 秒，b15 设置 3 秒搜索时首次约 5.6 秒。新 APK 安装后真机 5 项测试通过；前台运行的应用测试中，b10 在 19 路首次约 1.2 秒、第二次约 0.26 秒，b15 在 13 路首次约 5.3 秒。这些是引擎单次基准，不包含屏幕识别，也不能代表所有对局局面。真机后台冻结曾使 b15 测试超时；测试现在会把应用置于前台，与实际的屏幕共享前台服务更接近。

0.8.5 仓库改为公开，增加主界面按需检查更新：从 GitHub 公开发布接口读取版本并比较三段数字版本号，过滤草稿与非本仓库的 APK 链接；发现新版时由 Android 下载服务在应用内下载并显示进度，完成后调起系统安装界面。下载记录可跨应用重启恢复。联网只用于主动检查和下载更新，不在 APK 中嵌入访问令牌。
